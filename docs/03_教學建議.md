# 03 教學建議（給講師）

這份文件寫給要用這個專案教別人的講師：怎麼安排課程、每一步示範什麼、學員常卡在哪、怎麼出練習題。

## 課前準備

### 講師自己要做的

- [ ] 在自己電腦把五個步驟都跑過一次，記下每一步大概要等幾秒
- [ ] 先跑一次 `step4`，讓 Embeddings 模型下載好（現場下載 1 GB 很浪費時間）
- [ ] 準備投影片或白板，畫出「七塊積木」和「Agent 迴圈」兩張圖

### 請學員課前完成的

**模型和套件加起來要下載 10 GB 以上，一定要請學員在課前裝好**，不然整堂課都在等下載。

寄給學員的通知可以這樣寫：

> 上課前請先完成安裝：
> 1. 把專案資料夾複製到電腦
> 2. 照著 `docs/01_安裝教學.md` 安裝（或執行 `setup.ps1`）
> 3. 執行 `python src\step1_hello.py`，看到 AI 用中文自我介紹就完成了
> 4. 安裝遇到問題，請截圖寄給我
>
> 電腦需求：記憶體 8 GB 以上（建議 16 GB），硬碟空間 15 GB 以上

## 每一步的示範重點

### 步驟 1
- **先讓大家感受「慢」**：本機模型在 CPU 上跑，一題要等十幾秒。順便解釋為什麼雲端 API 要收錢（它們用很貴的 GPU 幫你跑）。
- **現場改 SystemMessage**：請學員提議一個好笑的角色，改完重跑，氣氛會很好。

### 步驟 2
- **單獨跑模板那一站**，讓學員看到「填好的題目」長什麼樣子，理解每一站的輸入輸出。
- 可以在白板上寫出資料一路的變化：`字典 → 填好的訊息 → AIMessage → 文字`。

### 步驟 3
- **先問學員**：「你覺得 AI 會自己去執行 get_price 這個函式嗎？」大部分人會說會。再用輸出的四則訊息證明：AI 只是「說」要用，執行的是 LangChain。
- **現場破壞 docstring**：把 docstring 改成「價格」兩個字，多跑幾次，讓大家看到 AI 不用工具、自己亂報價格。這是最能讓學員記住「docstring 很重要」的方式。

### 步驟 4
- **分兩段講**：先只看「搜尋測試」那段的輸出（相似度分數），讓學員理解「比的是意思不是字面」。等這個懂了，再講後面的 RAG Chain。
- **那個字典是最難懂的地方**，用「河流分成兩條支流再匯合」的比喻。學員常見的誤解見下面的 Q&A。
- **「你們有賣電視嗎？」這題**：如果 AI 亂編，正好拿來討論 prompt 該怎麼寫；如果它說不確定，就說明 prompt 裡的規則有效。

### 步驟 5
- **讓學員看工具呼叫紀錄**（`（呼叫工具：...）`那幾行），請他們猜下一題 Agent 會用哪個工具，再跑跑看。
- **示範記憶**：先問「推薦保濕產品」，再問「第一個多少錢」，接著輸入 `new`，再問一次「第一個多少錢」，AI 就不知道你在說什麼了。

## 學員常見問題與回答

**Q：那個字典 `{"context": ..., "question": ...}` 是不是「第一條路找不到，就走第二條路」？**
不是。兩條路**每次都同時跑**。第一條路拿問題去找資料，第二條路只是把原本的問題留著。最後兩個一起交給 AI。「找不到就換方法」要用 Agent 才做得到。

**Q：第一條路找到的是答案嗎？**
不是，找到的是「相關的資料」。retriever 像圖書館員，只幫你翻出相關的那幾頁；寫出答案的是最後的 AI。

**Q：為什麼價格不放進 RAG？**
因為價格和庫存會變。向量資料庫存的是建立當時的內容，不會自動更新。會變的資料要用工具即時查。

**Q：AI 為什麼有時候不用工具，自己亂回答？**
小模型的能力有限。可以試著：把 docstring 寫清楚、在 system prompt 強調「一定要用工具」、換大一點的模型。換成 Claude 這類大模型，這種情況會少很多。

**Q：模型記得我說過的話，是因為它有記憶嗎？**
沒有。模型本身沒有記憶，是 LangChain 每次都把之前的對話一起重新送過去。所以對話越長，每次送的內容越多，速度也越慢（用付費模型的話也越貴）。

**Q：為什麼要用本機模型，不直接用 ChatGPT 或 Claude？**
練習階段用本機模型免費、沒有用量限制，資料也不會傳出去。程式寫好以後，換成付費模型只要改 `config.py` 一行。

**Q：Embeddings 模型和 Gemma 4 是同一個東西嗎？**
不是。Embeddings 模型只負責「把文字轉成數字」，用來搜尋；Gemma 4 負責「理解和回答」。兩個是分開的模型。

**Q：相似度分數多少才算「像」？**
沒有標準答案，要看資料和 Embeddings 模型。本專案實測相關問題約 0.45 以上、無關問題約 0.35，所以設 0.4。換資料就要重新印出分數測一次。

## 課堂上可能發生的狀況

| 狀況 | 處理方式 |
| --- | --- |
| 學員電腦太慢，一題等超過一分鐘 | 請他把 `config.py` 改成 `gemma4:e2b`；或兩人共用一台比較快的電腦 |
| 學員忘記啟動虛擬環境 | 出現 `No module named` 就是這個，請他執行 `.\.venv\Scripts\Activate.ps1` |
| 同一題每個學員的回答都不一樣 | 正常現象，AI 的回答本來就有隨機性。可以藉此說明 `temperature` |
| AI 的回答跟預期不同 | 不要急著說「壞了」，先一起看工具呼叫紀錄，討論為什麼，這是最好的學習時機 |

## 實測踩雷紀錄（很適合上課討論）

開發這個專案時，實際踩到六個坑。坑 1～4 是用 8 個範例商品開發時遇到的，坑 5、6 是換成網站真實資料後遇到的（坑 6 是實際模擬顧客對話時發現的）。每一個都是學員之後一定會遇到的典型問題，建議在步驟 5 結束後拿出來討論。

### 坑 1：AMD 顯卡讓 Ollama 當掉

| | 內容 |
| --- | --- |
| 現象 | 第一次執行就出錯：`llama-server process has terminated ... ErrorOutOfHostMemory` |
| 怎麼找到原因 | 看錯誤訊息是 Ollama 傳回來的，不是 Python 程式的錯；再看 Ollama 的伺服器紀錄，發現是 Vulkan（顯卡）配置記憶體失敗 |
| 解法 | `ChatOllama(num_gpu=0)` 強制只用 CPU |
| 教學重點 | **看錯誤訊息是從哪一層來的**：Python？LangChain？Ollama？顯卡？找對層才找得到原因 |

### 坑 2：只說不做的客服

| | 內容 |
| --- | --- |
| 現象 | 客服每題都回答「我馬上幫您查詢，請稍等～」，然後就結束了，一個工具都沒用 |
| 原因 | 小模型學到了客服「講話的樣子」，卻沒有真的去做；prompt 沒有明確要求它直接行動 |
| 解法 | System prompt 第一條加上「需要資料時直接呼叫工具，不要先跟顧客說我幫您查一下」 |
| 教學重點 | **小模型需要非常具體的指示**。告訴它「該做什麼」之外，也要告訴它「不要做什麼」 |

課堂活動：讓學員把這條規則刪掉，跑 `--demo`，親眼看到客服變成只說不做。

### 坑 3：「那第一個多少錢？」查錯商品

| | 內容 |
| --- | --- |
| 現象 | 客服推薦了保濕乳液，顧客問「第一個多少錢」，結果查成防曬乳的價格 |
| 第一次嘗試（失敗） | 改 system prompt，說明「第一個」是指回答給顧客看的清單。還是錯 |
| 真正的原因 | 搜尋結果裡防曬乳（0.668）和保濕乳液（0.666）分數幾乎一樣，防曬乳排第一，模型就跟著搞混 |
| 解法 | 改成混合搜尋（意思相似度 + 關鍵字重疊），保濕乳液穩定排第一，連跑 3 次都答對 |
| 教學重點 | **問題不一定出在你以為的地方**。prompt 改不好時，往前一站檢查搜尋結果。把每一站的輸出印出來看，是除錯最有效的方法 |

### 坑 4：不管預算、亂推卸妝油，甚至編造商品

| | 內容 |
| --- | --- |
| 現象 | 顧客說「乾燥肌男士、500 元以內」，客服推薦 680 元的乳液和 580 元的卸妝油，完全沒提超出預算 |
| 第一次修（失敗） | 加 `max_price` 參數，工具只回傳預算內的商品。結果預算內只有油性肌用的化妝水，模型覺得不對，**竟然編造了兩個不存在的商品**，回答裡還夾雜亂碼 |
| 真正的解法 | 工具同時列出「預算內的候選」和「最相關但超出預算的商品」，並提醒「候選不一定符合需求」；prompt 加上「寧可少推薦，也不要硬湊」 |
| 結果 | 連跑 3 次都正確：說明化妝水不適合乾燥肌，推薦乳液和乳霜並標明超出預算；卸妝油不再出現 |
| 教學重點 | **數字比較交給程式，語意判斷交給模型。** 另外，只給模型錯誤的選項時，它會想辦法「生出」答案，就容易亂編；要給它正確的選項 |

課堂活動：請學員猜猜看「只回傳預算內商品」的版本會發生什麼事，再公布模型編造商品的結果。這是讓學員理解「AI 幻覺從哪裡來」最直接的例子。

### 坑 5：換成真實資料後，「卸妝」找不到卸妝液

| | 內容 |
| --- | --- |
| 背景 | 前四個坑是用 8 個範例商品測試時遇到的。換成網站上 63 個真實商品後，又出現新問題 |
| 現象 | 搜「卸妝」，名稱裡就有「卸妝液」「潔顏油」的兩個商品沒被找出來，反而跑出護理霜 |
| 原因 | 混合搜尋原本只從意思搜尋的前 6 名裡加關鍵字分數。真實商品文案很長、又有很多 emoji，Embeddings 模型抓不準，那兩個商品在意思搜尋只排第 20、22 名，第一步就被淘汰 |
| 解法 | 商品少於 200 個時，每個商品都參加關鍵字評分；有預算時，先篩預算再取最相關的 |
| 教學重點 | **用範例資料測過不代表真實資料也沒問題。** 資料變多、文案變長，原本的參數就可能不夠用，一定要用真實資料再測一次 |

### 坑 6：客服編出不存在的「宅配服務」

| | 內容 |
| --- | --- |
| 現象 | 顧客問「你們家有宅配？」，客服回答「我們有提供宅配服務的喔！運費 60 元」。但本店只有 7-11 賣貨便取貨付款 |
| 原因 | FAQ 裡沒有「宅配」這題。搜尋找到最像的是「運費怎麼算」，模型看到「運費 60 元」，就自己推論成「有宅配、運費 60 元」 |
| 解法 | 1. FAQ 補上「有宅配嗎？」，答案來自網站服務條款<br>2. System prompt 明寫「配送只有 7-11 賣貨便，沒有宅配」<br>3. 加規則「店家規則沒寫的服務，不能說有，不可以自己推論」 |
| 結果 | 問宅配、問寄全家，都正確回答沒有 |
| 教學重點 | **AI 最危險的錯誤，是自信地講出錯的事。** 資料庫「沒有寫」，不代表 AI 會說「不知道」；它常常會從相近的資料「推論」出答案。重要的事實要明寫，也要明寫「不能做什麼」 |

順便發現：顧客說「樹林區學勤路」，但學勤路其實在**三峽區**。新的「找 7-11 門市」工具會比對門市清單，提醒顧客確認地址。

修完宅配以後，同一段對話還有四個小瑕疵，修法都很有代表性：

| 小瑕疵 | 修法 | 屬於哪一類 |
| --- | --- | --- |
| 說「7-11 賣貨便和取貨付款**這兩種**方式」 | prompt 寫明「這是一種方式，不要說成兩種」 | 把話講清楚 |
| 推薦防曬時混進面膜 | 工具只回傳有命中關鍵字的預算內商品 | 程式先過濾 |
| 漏列最符合的學勤門市 | 門市結果分組，標明「一定要列出這一組」 | 資料整理清楚 |
| 同一個商品介紹兩次、回答太長太慢 | 程式去除重複商品；prompt 限制最多推薦 3 個 | 程式＋prompt |

> **教學重點：能用程式保證的，就不要交給模型。** 過濾、去重複、分組這些事，程式做 100% 正確；模型只負責理解和表達。

### 六個坑的共同教訓

> 1. 先確認是哪一站出問題，再動手修。
> 2. 每次只改一個地方，改完重跑，確認有效。
> 3. 同一個測試跑好幾次。AI 的回答有隨機性，跑一次對不代表穩定。
